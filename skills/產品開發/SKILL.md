# 產品開發 agent

把一個想法或原型，做成可上線的工具或網頁。

## 什麼時候用
- 要做線上工具（如呼吸放鬆工具）、課程網站、行銷頁。

## 步驟
1. 釐清目標：給誰用、解決什麼、成功長怎樣。
2. 最小可動版本先做出來（前端優先，能看能點）。
3. 對齊品牌：調性、視覺套用練息場知識庫與設計規範。
4. 自我檢查：跑過 QA 程式審查，抓 bug 與品質問題。
5. 判斷風險級別（見 CLAUDE.md 風險分級），該找人就找人。
6. 放行後部署（GitHub → Cloudflare）。

## 風險提醒
- 只動前端 = 低風險；動到資料庫/後端 = 中風險，要安妮確認；碰金流/個資 = 高風險，要主理人確認。

## AI 串接管理介面標準（接任何 AI 金鑰都照這套）
任何專案要串 AI（Gemini／Claude／OpenAI…）時，管理介面一律照這套，並遵守安全原則。
源頭範例＝ deck-studio 的「新增頁面」AI 區（repo: jointoenjoy/deck-studio；後端 `functions/api/gen.js`、前端 `index.html` 的 aimodel 區與 `AI_PROVIDER` 設定）。

### 介面四件套（缺一不可）
1. **模型下拉**：即時去該 AI 後台抓「當下可用模型」清單讓使用者選——不要寫死、不要每週排程，即時抓最新。
2. **團隊密碼解鎖**：輸入密碼才能用；密碼只存使用者本機瀏覽器、不上傳。
3. **用量與金額**：顯示本次＋累計的 token 數與費用。
4. **AI 後台超連結**：連回「該家 AI」後台（看真實用量／設定）。用一個 `AI_PROVIDER = { name, console }` 設定控制名稱＋連結——連哪家 key 就連哪家後台，未來換家只改這一處。

### 安全原則（紅線：金流／金鑰）
- 金鑰一律存後端環境變數（如 Cloudflare 環境變數），**絕不寫進前端公開頁**。
- 前端只透過自家後端代理（如 `/api/gen`）呼叫 AI，金鑰永不外露。
- 公開頁**必加密碼鎖**，避免陌生人燒額度。

## 前端工具加雲端儲存的標準模式（從 localStorage 升級到跨裝置永久保存）
把純前端工具（資料原本存瀏覽器 localStorage、換裝置／清快取就遺失）升級成「跨裝置永久保存」時，照這套：

- **架構**：Cloudflare KV（存資料）＋ Pages Functions 後端代理（`functions/api/xxx.js`）＋ 密碼鎖（沿用環境變數密碼）。
- **最安全的做法**：不要改現有存檔邏輯。改成「把本機 localStorage 的內容**同步上雲／從雲端還原回 localStorage**」——存就是 POST 上去，載入就是寫回 localStorage 再 reload。現有讀寫邏輯一行都不用動，風險最低。
- **存取控制**：公開頁一定要密碼鎖（後端驗證），避免陌生人讀寫雲端資料或燒額度。
- **KV 小技巧**：一筆資料一個 key（`prefix:<id>`），metadata 放名稱／時間，列表時不必讀每筆值；單值上限約 25MB，含大圖要注意。
- 源頭範例＝ deck-studio 的簡報雲端保存（`functions/api/decks.js` ＋ `index.html` 的 cloud 系列函式、`wrangler.toml` 的 KV binding）。
