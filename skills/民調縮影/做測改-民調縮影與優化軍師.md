## 一、緣起（心法）
源自 Opus 4.8 Build Day 的兩條心法：**難的不是生出東西，是相信它對** → ①聰明收斂 ②對抗式驗證。
落地成一對搭檔：**民調縮影＝廉價風洞先「測」，優化軍師＝根據測出來的給「改」**，兩隻組成「做→測→改」閉環。

## 二、民調縮影（✅ 已做，在 `skills/民調縮影/`）
- **一句話**：給產物＋問題 → 一組「加權代表 panel」各自反應、打分 → 加權彙整成 topline＋分眾＋心聲＋風險。幾秒、幾乎不花錢、可重複比較。
- **省 token 核心**：不模擬上萬人，用 10–16 個「交叉具體」原型人物加權，**一題一次推論掃全 panel**（不是一人一次、不開常駐 agent）。panel 存成 JSON 一次做好永久重用。
- **現成 panel**：`台灣母體-panel.json`、`高科技產業-panel.json`、`行銷產業-panel.json`。
- **校準回測（重要教訓）**：拿已知真實值盲測比對。高科技 panel 對「HRV App 兩週留存」原估 25–30%，真實 wellness App 30 天留存僅 3–8% → **高估 4–6 倍**。已寫修正規則：**留存／養成習慣類預測一律大幅下修**；下載／試用類較可信。
- **紅線與限制**：敏感／認同題不準、別報假精準（報區間）、**panel 全是合成虛構人物、不碰真實個資**、不取代真人（高風險決策要真人小樣本複驗）。

## 三、優化軍師（🟡 待做 — 這支是新對話要定案＋試做的）
- **定位**：吃「產物＋民調縮影結果」→ 輸出 ①**排序過的優化清單**（先改 CP 值最高的）②**改寫示範**（標題／CTA／文案各 3 版）③**預期影響** ④**下一輪要再丟回民調縮影測什麼**。
- **內建框架**（借公開框架、不照裝第三方 skill）：PAS（痛點-煽動-解方）、AIDA、StoryBrand、CRO 檢查表。
- **綁品牌紅線**：Apple 藍白灰、不說教、**不放真實人名**、溫暖×科學實證。

## 四、做→測→改 怎麼連起來
產物 →〔民調縮影：測〕→〔優化軍師：給改法〕→ 改 →〔民調縮影：再測同 panel 比較〕→ 收斂。
控制變因＝同一個 panel 跑前後兩版，差異才有意義。
