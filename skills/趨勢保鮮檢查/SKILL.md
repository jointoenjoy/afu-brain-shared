# 趨勢保鮮檢查

把「趨勢洞察」類的知識定期體檢，揪出過時的，**列勾選清單給大寶**核可後才刪／更新——**不自動刪**。

## 什麼時候用
- 大寶說「做趨勢保鮮檢查」「檢查趨勢有沒有過時」時。
- 建議**每月一次**（由排程 trigger 自動叫起，或大寶手動觸發）。

## 掃描範圍
- `品牌知識庫/趨勢洞察/` 底下所有 `.md`。

## 保鮮期規則（判斷邏輯藏這裡，不寫進每張卡）
讀每張卡 frontmatter 的 `收錄日`，算「已收錄幾個月」，對照保鮮期：
- `類型: 趨勢洞察` → 保鮮期 **6 個月**。
- 工具／版本類（會隨版本變動的） → **3 個月**。
- 沒標類型 → 預設 **6 個月**。
- 超過保鮮期 → 標「**待複查**」。

## SOP（每次照跑）
1. 掃描範圍內每張卡，讀 frontmatter 的 `收錄日`、`類型`、`來源`。
2. 算每張卡的「年齡」，依保鮮期規則挑出「待複查」的。
3. 對每張待複查的卡，用 WebSearch 查最新狀態，判斷三選一：
   - ✅ **仍有效**（趨勢還在）→ 建議把 `收錄日` 更新成今天（續鮮）。
   - 🔄 **要更新**（部分過時／有新數據）→ 摘要該補、該改什麼。
   - ❌ **已過時**（趨勢消退／被取代）→ 建議刪除。
4. **列成勾選清單給大寶**：每條 = 標題 ＋ 收錄日 ＋ 建議動作 ＋ 一句理由（可複選）。
5. 大寶勾完才動手：更新就改檔、刪除就刪檔，`commit` + `push`。
6. 重建 aiflow 阿福頁（趨勢卡只露「收錄日」）。

## 紅線（重要）
- **絕不自動刪**。刪除是破壞性、救不回，一律先給大寶勾選核可（符合大腦「該交回人類就交回」）。
- 不確定一條趨勢是否過時 → **列進清單問**，不要自己判生死。

## 給人看的（aiflow 阿福頁）
- 每張趨勢卡只露「**收錄日**」。保鮮期、「待複查」狀態都是內部判斷，不上頁面。
