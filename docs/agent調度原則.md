# 阿福的 agent 調度原則（何時自己做、何時派分身）

> 目標：讓阿福當**總指揮**，別當搬磚工。重的、雜的、要讀很多/搜很多的活，丟給用完即丟的分身，阿福只留結論——這樣不浪費 token、不變慢、不變笨。

## 一、三隻分身（實體在 `.claude/agents/`，Claude Code 自動依 description 派活）

| 分身 | 對應大類 | 接什麼活 | 擁有的 skills（`category` 對應） |
|---|---|---|---|
| `insight-research` | 洞察研究 | 重搜尋／重讀取的研究調查 | 市場調研、UX 體驗研究、趨勢保鮮檢查 |
| `product-marketing` | 產品行銷 | 要實際做出成品的製作活 | 視覺設計、社群內容、產品開發 |
| `ops-governance` | 營運治理 | 把關／審查／分級／盤點 | QA 程式審查、資安分級 |

**對應規則**：一個 skill 屬於哪隻分身，看它 `SKILL.md` 的 `category`。

## 二、判斷：阿福自己做 vs 派分身

### 阿福自己做（不派分身）當——
- 任務**輕、單步**：回個問題、改一句話、小編輯。
- **相依性高、要來回**：需要你即時回饋、邊聊邊調的事。
- 只需讀 **1–2 個檔**、不需大量搜尋。
- 需要**總管視角**串全局：拆任務、做決策、把關紅線、最後 commit/push 與上架。

### 派給下面分身當——
- **重讀取**：要掃很多檔／整個知識庫。
- **重搜尋**：要多次 WebSearch／WebFetch 的研究、調研。
- **可平行、廣度型**：多個獨立子題可同時查（可同時派多隻）。
- **產出大、中間雜**：做完只需要一份結論／成品回來。
- **要脈絡隔離**：某專屬任務，不想污染主桌（也含安全：碰外部資料的隔離）。

> 一句話：**「要讀很多 or 搜很多 or 做很多，而且最後只需要結論」→ 派分身。** 反之自己做。
> 別無腦全拆——派分身會增加總 token 與協調成本，緊密相依的小事自己做更快更省。

**搜尋預設輕量（大寶定調）**：所有查資料**先輕量**——1–2 個 WebSearch、夠用就停；**只有大寶明說「深入／徹底／多方查證」才升級**成重型研究或派研究分身做 fan-out。

## 三、分身的鐵則（已寫進各 agent 定義）

1. **只回結論**：分身在自己的獨立脈絡做完，把精煉結論／成品交回，**中間原始資料不回傳**——這是「讓阿福保持輕」的關鍵。
2. **不 commit／不 push／不部署**：收尾、上架、碰紅線的判斷，一律交回阿福（單一收尾者，避免打架）。
3. **守三條紅線**：碰使用者資料／金流／改大腦 → 停，交回阿福。
4. **權限最小化**：只給該任務需要的工具與脈絡（研究/審查分身無寫檔權、製作分身才有）。

## 四、人類怎麼下指令

照舊——**直接用中文講你要幹嘛就好**，不用點名分身。阿福會自己判斷該自己做、還是派哪隻分身。
- 想強制走某條路：直接講「**派研究分身去查…**」「**叫 QA 審一下**」也可以。

## 五、可調的旋鈕（省錢/提速）
- 想更省：可在某隻分身定義加 `model:`，把「單純掃描型」的活（如趨勢保鮮、QA 初掃）指到較快較省的模型；需要深度推理的研究維持高階模型。預設不指定＝沿用阿福的模型。
